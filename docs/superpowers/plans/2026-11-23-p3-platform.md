# P3 Platform & App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Owner:** P3 · **Branch:** `core/platform` (branched from `main` after the day-0 merge; small PRs are welcome) · **Runs in parallel with:** the P1 and P2 plans. It builds and tests against whatever is in `DATA_TYPES`: the placeholders at first, the real data types once merged.

**Goal:** Build the shared classical models, the CNN training loop, evaluation, the robustness sweep, the `python -m radar.core.run` command and the load-only Streamlit demo, then run the integration before the review.

**Architecture:**
- `radar/core/` holds pure functions over the contract (`DataType`, `DataBundle`). `run.py` drives them and writes files under `results/` and `models/`.
- `app/` only reads those files. It calls `load`, `perturb`, `render`, `features` and `to_cnn_input` through the contract, and never fits anything.

**Tech Stack:** scikit-learn, xgboost, torch (CPU), pandas, joblib, matplotlib, streamlit (including `streamlit.testing.v1.AppTest`)

**Spec:** `docs/superpowers/specs/2026-11-23-mvp-implementation-design.md` (the "P3 Platform & App", "Integration" and "Budgets" sections)

## Global Constraints

- Edit only `radar/contracts.py`, `radar/registry.py`, `radar/core/`, `app/`, `tests/test_core.py`, `requirements.txt`, `README.md` and `.gitignore`. Never edit `radar/sar/` or `radar/signal/`. The contract is frozen.
- Use a data type only through `DATA_TYPES` and the `DataType` methods. Never import `radar.sar` or `radar.signal` from `core/` or `app/`.
- Model names, in this order: `("svm", "rf", "xgb", "cnn")`.
- File layout. `<root>` is `$RADAR_ROOT` if it's set, otherwise the repo root:
  - `<root>/models/<data>/<source>/{svm,rf,xgb}.joblib`, `cnn.pt` (state_dict)
  - `<root>/results/<data>/<source>/summary.csv`, `robustness.csv`, `breakdown.csv`, `raw/metrics.json`
- `summary.csv` columns: `model, accuracy, macro_precision, macro_recall, macro_f1, ff_accuracy, ff_precision, ff_recall, ff_f1, train_seconds, infer_ms_per_sample`
- `robustness.csv` columns: `model, level, accuracy, ff_accuracy`
- `breakdown.csv` columns: `model, key, bin_lo, bin_hi, n, accuracy`
- Friend/Foe = the argmax type prediction mapped through `foe_classes` (D6). Foe is the positive class for P/R/F1. The Friend/Foe confidence is the type confidence.
- The app never trains (rule 4). When a file is missing, the app shows `python -m radar.core.run --data <data> --source <source>` and calls `st.stop()`.
- The Friend/Foe note, verbatim, on the Predict and Compare Models pages: "Friend/Foe is a documented grouping of object-type classes (see docs/decisions.md D6), derived from each model's type prediction. It is not independent ground truth."
- Everything is seeded (`--seed`, default 0). `torch.manual_seed`, numpy `default_rng` and `random_state` all get the seed.

## Review Focus

- **The app on a fresh clone, with no models trained yet.** Every page must show the run command, not a traceback.
- **A model subset.** Running `--models svm cnn` must write a 2-row summary, and the app must show only the models present.
- **Real data with no clean copies.** When `X_test_clean` is `None`, the sweep and the Predict page's "generate" must perturb `X_test` and label it "added noise".
- **A constant metadata key.** Synthetic SAR's `depression_deg` is always 15. Breakdown binning must give one bin and not crash.
- **A single-sample prediction** (`x[None]`) must give probabilities that sum to 1 for every model.

### Task 2: Classical models and the generic CNN loop

**Files:**
- Create: `radar/core/classical.py`, `radar/core/deep.py`
- Test: `tests/test_core.py` (append)

**Interfaces:**
- Produces:
  - `classical.build_classical(seed: int) -> dict[str, estimator]` with the keys `svm`, `rf` and `xgb`:
    - `svm`: `make_pipeline(StandardScaler(), SVC(kernel="rbf", probability=True, random_state=seed))`
    - `rf`: `RandomForestClassifier(n_estimators=200, n_jobs=-1, random_state=seed)`
    - `xgb`: `XGBClassifier(n_estimators=200, max_depth=6, learning_rate=0.1, tree_method="hist", random_state=seed)`
  - `deep.train_cnn(model: nn.Module, X: np.ndarray, y: np.ndarray, seed: int, max_epochs: int = 30, patience: int = 5, batch_size: int = 64, lr: float = 1e-3) -> nn.Module`:
    - uses Adam and cross-entropy
    - holds out a stratified `max(int(0.1 * N), n_classes)` samples for early stopping on validation loss, so tiny `--quick` data still splits
    - restores the best weights
    - returns the model in eval mode
  - `deep.cnn_proba(model: nn.Module, X: np.ndarray, batch_size: int = 256) -> np.ndarray`: softmax probabilities, computed under `no_grad`

### Task 4: Robustness sweep and breakdown

**Files:**
- Create: `radar/core/robustness.py`
- Test: `tests/test_core.py` (append)

**Interfaces:**
- Produces:
  - `sweep(dt, bundle, predictors: dict[str, Callable], seed: int) -> pd.DataFrame`. Columns: `model, level, accuracy, ff_accuracy`. For each level in `dt.levels`, it scores the predictors on `dt.perturb(source_X, level, seed)`, where `source_X` is `bundle.X_test_clean` if it isn't `None`, otherwise `bundle.X_test`. The DataFrame's `attrs["added_noise"]` is `True` when `bundle.X_test_clean` is `None`.
  - `breakdown(bundle, preds: dict[str, np.ndarray]) -> pd.DataFrame`. Columns: `model, key, bin_lo, bin_hi, n, accuracy`. `preds` holds the predicted indices on the unperturbed `X_test`. Each `meta_test` key is split into `min(8, number of unique values)` equal-width bins, and empty bins are dropped.

- [ ] **Step 1: Write the failing tests**

```python
from dataclasses import replace
from radar.core.robustness import sweep, breakdown

def test_sweep_and_breakdown_shapes():
    dt = DATA_TYPES["sar"]; b = subsample(dt.load("synthetic", 0), 4, 2, seed=0)
    n = len(b.class_names); oracle = lambda X: np.full((len(X), n), 1 / n)
    df = sweep(dt, b, {"u": oracle}, seed=0)
    assert list(df.columns) == ["model", "level", "accuracy", "ff_accuracy"] and len(df) == len(dt.levels)
    assert df.attrs["added_noise"] is False
    assert sweep(dt, replace(b, X_test_clean=None), {"u": oracle}, seed=0).attrs["added_noise"] is True
    meta = {"const": np.full(len(b.y_test), 15.0), "angle": np.linspace(0, 359, len(b.y_test))}
    bd = breakdown(replace(b, meta_test=meta), {"u": b.y_test.copy()})
    assert (bd[bd.key == "const"].shape[0] == 1) and (bd.accuracy == 1.0).all()
    assert bd[bd.key == "angle"].n.sum() == len(b.y_test)
```

  - `bundle(data, source)`: `@st.cache_resource` around `DATA_TYPES[data].load(source, seed=0)`

- What each page shows:
  - **Home:** title, a one-paragraph description, `FF_NOTE`.
  - **Predict:**

  - **Robustness:** a line chart of accuracy vs level, one line per model, with the x-axis labelled `dt.perturbation`. A "(added noise)" suffix appears when it applies. Below it, a bar chart of the breakdown for a selected metadata key.
